```markdown
# meeting-assistant

LLM-ассистент, который превращает неструктурированные заметки о встрече
в структурированный протокол и выгружает его в `.docx`. Плюс — реестр
скилов с HTTP API для управления ими.

Проект состоит из трёх частей:

1. **Скил** `meeting-to-protocol` — промпт-артефакт, который учит LLM
собирать протокол из сырых заметок.
2. **Конвертер** — markdown-протокол → `.docx` через `python-docx`.
3. **Реестр скилов** — загрузка, валидация, hot reload + FastAPI `GET /skills`.

Все три части покрыты тестами. Скил прогнан через GigaChat: классификатор
выбирает его **10/10** раз корректно, конвертер собирает `.docx` **3/3** раза.

## Реестр скилов: HTTP API

```bash
uvicorn app.api.main:app --reload
```

Открой http://127.0.0.1:8000/docs — Swagger.

Эндпоинты:

- `GET /skills` — список всех скилов.
- `GET /skills?q=<подстрока>` — поиск по `name` и `caption` (case-insensitive).
- `POST /skills/reload` — перезагрузить реестр (бонус, в ТЗ не требуется).

Пример ответа:

```json
[
{
    "name": "meeting-to-protocol",
    "caption": "Заметки встречи → протокол",
    "description": "Преобразует неструктурированные заметки...",
    "has_files": true
}
]
```

## Формат протокола

Строгий контракт между LLM и конвертером. Любая LLM-ответ
разбирается однозначно, без эвристик.

```markdown
# Протокол встречи: <Тема>

**Дата:** <YYYY-MM-DD | Не указано>
**Участники:** <Имя1, Имя2 | Не указано>

## Обсуждение
- <пункт>

## Решения
- <пункт>

## Задачи

| Задача | Ответственный | Срок |
|---|---|---|
| <текст> | <имя | Не указано> | <YYYY-MM-DD | Не указано> |
```

Жёсткие правила:

- Ровно три секции H2 в фиксированном порядке.
- Единый плейсхолдер — `Не указано`.
- Даты — строго `YYYY-MM-DD`.
- Таблица задач — pipe-таблица с точной шапкой.

Парсер толерантен к мелочам (пробелы, выравнивание, обёртка в ` ```markdown `),
но строг к структуре.

## Прогон через GigaChat

Скил проверен на живой LLM (базовая `GigaChat`).

### Прогон заметок → протокол

```bash
python -m scripts.run_skill
```

Для каждого примера в `examples/`:
1. Отправляет `notes.txt` + тело `SKILL.md` как system prompt.
2. Получает markdown-протокол.
3. Парсит через `parse_protocol`.
4. Собирает `.docx`.

**Результат:** 3/3 примера распарсились корректно.

### Прогон классификатора

```bash
python -m scripts.run_classifier
```

Прогоняет 10 запросов из `eval_queries.md` через GigaChat
с инструкцией «выбери скил или верни `none`».

**Результат:** 10/10 — все 6 релевантных запросов триггерят скил,
все 4 нерелевантных — нет.

### Что показал прогон

GigaChat (базовая модель) **не идеально следует инструкциям**.
В процессе прогона выявлены особенности:

- **Оборачивает ответ в ` ```markdown `.** Парсер срезает обёртку в `_normalize`.
- **Выравнивает колонки таблицы пробелами.** Парсер сравнивает
нормализованные ячейки, а не строку целиком (`_is_header_row`).
- **Иногда путает формат даты** (`12-09-2024` вместо `2024-09-12`).
Правило в промпте усилено явным запретом.
- **Иногда добавляет «Автора протокола» в участников.** Промпт
усилен явным запретом на роли без имён.
- **Галлюцинирует год** (`2023` вместо `2024`). Промпт уточняет
правило работы с годом.

Все эти особенности **задокументированы и обработаны**: где-то
в парсере, где-то в промпте. Это часть работы со скилом — подгонять
его под реальное поведение LLM, а не под идеальное.

## Что осознанно упрощено

- **Реестр in-memory**, без БД. Данные живут в памяти процесса.
- **Нет аутентификации в API.** Предполагается внутренний контур.
- **Нет watcher-а файловой системы.** Reload — вручную через
`POST /skills/reload` или перезапуск.
- **Парсер не валидирует «существование» даты** (`2024-13-45` пройдёт).
Формат проверяется, семантика — нет.
- **Классификатор в `run_classifier` — один скил.** В реальной системе
он получает описания всех скилов и выбирает один или `none`.

---

## Известные ограничения

- **GigaChat базовая модель** хуже держит формат, чем `GigaChat-Pro`
или `GigaChat-Max`. Для прода — использовать старшие модели.
- **`verify_ssl_certs=False`** в `GigaChat(...)` — временное решение
для обхода сертификатов Сбера. В проде — настроить корневые
сертификаты.
- **Скил работает только на русском.** Англоязычные заметки не тестировались.
